# DEAD PEDAL

A cooperative zombie-survival cycling game prototype. Your pedalling is the
controller: keep your speed up, stay together, and escape the town before the
horde catches the group.

**Status:** first playable prototype. One mission (*Escape the Town*),
single-player and 2–6 player LAN/host-and-join multiplayer. Cycling input is
**simulated with the keyboard** for development; no smart-trainer support yet.

---

## 1. Running the game

1. Install **Godot 4.7** (standard build, not .NET) from
   <https://godotengine.org/download>. Godot 4.4+ should also work.
2. Start Godot, click **Import**, and select `project.godot` in this folder.
3. Press **F5** (or the ▶ Play button, top-right) to run the game.

The first time you open the project, Godot imports it, which takes a few
seconds. Everything (town, models, sounds) is generated by code, so there are
no asset files to download.

### Controls (development: simulated cycling)

| Key | Simulates |
|---|---|
| `1` – `5` | Steady effort: recovery, easy, normal, hard, all-out (fractions of your FTP) |
| `0` or `` ` `` | Stop pedalling |
| `W` / `↑` (hold) | Push harder; release and power falls back to your steady level |
| `Space` (hold) | Sprint, with a fast ramp to max power |
| `S` / `↓` (hold) | Stop pedalling immediately |
| `F1` | Show/hide the input help panel |

A typical ride: press **3** (normal) to cruise, hold **Space** when the horde
surges, and press **4** or hold **W** at the gate.

### The mission: *Escape the Town* (~3–4 minutes)

1. **Departure:** ride out through the abandoned town.
2. **Pursuit:** the horde spots you. The HORDE meter (bottom-right) shows how
   close it is. It occasionally **surges**, so sprint!
3. **Locked gate:** you stop at the quarantine gate. Keep pedalling: everyone's
   effort winds the winch. The green lamps on the gate and the bar show progress
   while the horde shuffles closer.
4. **Final escape:** the gate opens; race to the green flare at the extraction point.
5. **Results:** time, distance, top speed, gate objective, and **Replay**.

You fail if the horde reaches the **rearmost** rider, so the group is only as
safe as its slowest member.

## 2. Multiplayer (2–6 players)

**On one computer (for testing):** run two copies of the game.

- In the Godot editor, open **Debug → Customize Run Instances…**, tick
  **Enable Multiple Instances**, set the count to **2**, and press F5. Two
  windows open.
- Window A: **HOST GAME**. Window B: **JOIN GAME** (IP `127.0.0.1`).
- In window A, press **START MISSION**. Each window responds only to the
  keyboard while it has focus, so click a window before "pedalling" in it.

**On two computers on the same network (LAN):**

- Host: click **HOST GAME**. The lobby shows this computer's LAN IP address(es).
- Other player: type that IP into the box next to **JOIN GAME** and click it.
- The host may need to allow Godot through the firewall (UDP port 7777).

**Over the internet:** not tested yet. It needs the host to forward UDP port
7777 on their router (or a VPN such as Tailscale/ZeroTier, which makes it
behave like a LAN). This prototype has no matchmaking or relay server.

**How it's synchronised:**
- The host is authoritative for the mission: stage, horde position, gate
  progress, success/failure.
- Each player is authoritative only for their own cyclist (driven by their own
  input) and sends its distance/speed/effort 20×/s.
- Solo play runs exactly the same code path, using Godot's offline peer.

## 3. Fairness: why a weaker rider isn't a liability

- **Effort is relative to your FTP.** Set your FTP on the title screen. Speed
  comes from *effort as a fraction of your own fitness*, so a 150 W-FTP rider
  at threshold is as fast as a 300 W-FTP rider at threshold.
- **Slipstream:** riding 1.5–10 m behind a teammate gives +10% speed, so
  stronger riders can pull others along.
- **The gate adds up the team's effort**, so a strong rider can carry more of
  the load. Teams need more total effort than a solo rider, but less than
  double, so working together pays off.

## 4. Project structure

```
project.godot
scenes/
  ui/main_menu.tscn              Title screen + lobby
  mission/escape_the_town.tscn   The mission (open this to tweak the level)
  cyclist/cyclist.tscn           One rider (tune the RideModel here)
  zombies/zombie.tscn            One zombie
scripts/
  autoload/
    cycling_input_manager.gd     Global access to the local rider's effort
    multiplayer_manager.gd       Host / join / roster / load mission everywhere
    dev_tools.gd                 Command-line test options (no effect normally)
  input/
    cycling_input_source.gd      THE INTERFACE all input sources implement
    simulated_cycling_input.gd   Keyboard simulation (development only)
    scripted_cycling_input.gd    Fixed power profiles for automated tests
  cyclist/
    ride_model.gd                Effort -> speed (acceleration, momentum, ...)
    cyclist_controller.gd        Moves a rider along the route; network sync
    cyclist_model.gd             Placeholder bike + rider with pedalling IK
  camera/camera_controller.gd    Smooth chase camera; pulls back when in danger
  zombies/
    zombie_director.gd           The horde threat (host-simulated) + all zombies
    zombie_controller.gd         One zombie: model, shamble, behaviours
  mission/
    mission_manager.gd           Stages, rules, authority, results
    gate_objective.gd            Cooperative gate (team effort)
    extraction_zone.gd           Safe zone visuals
  world/
    route.gd                     The road path; everything moves by distance along it
    town_builder.gd              Procedural road, buildings, props, lights
    prop_factory.gd, mesh_kit.gd Placeholder models from primitive shapes
  ui/hud_controller.gd, route_progress_bar.gd, main_menu.gd
  audio/sfx_synth.gd, mission_audio.gd   Procedural placeholder sound
shaders/                         Road, facade, ground, danger vignette
tests/unit_tests.tscn            Automated checks
```

### Tuning (all in the Inspector)

- **Mission timings and distances:** select the `Mission` root node in
  `escape_the_town.tscn` (gate distance, extraction distance, pursuit start, …).
- **Horde difficulty:** the `Zombies` node (speeds, surges, catch-up, danger range).
- **Gate difficulty:** the `Gate` node (effort-seconds per rider, team scaling).
- **Speed feel:** open `cyclist.tscn`, select the root, expand **Ride Model**.
- **Camera:** the `Camera` node.
- **Road shape:** the `Route` node's **Control Points**.

### Adding a real smart trainer later

Create a new script that `extends CyclingInputSource` and implements
`get_power_watts()`, `get_cadence_rpm()`, `is_input_valid()`,
`get_source_type()` and `get_source_name()`. Then call
`CyclingInputManager.set_source(YourTrainerInput.new())`. Movement, zombies,
missions and networking don't need to change. (Bluetooth FTMS / ANT+ would
need a GDExtension or a small companion app; not part of this prototype.)

## 5. Testing

Unit tests (input, ride model, route, gate, horde):

```
godot --headless --path . res://tests/unit_tests.tscn
```

Full automated mission runs (no window; the "autopilot" replaces the keyboard):

```
# Solo: a strong rider should escape (exit code 0)...
godot --headless --path . -- --solo --autopilot=230 --timescale=4 --exit-on-results
# ...a weak rider should be caught (exit code 2)
godot --headless --path . -- --solo --autopilot=90 --timescale=4 --exit-on-results

# Two networked instances (run in two terminals):
godot --headless --path . -- --host --auto-start=2 --autopilot=220 --timescale=3 --exit-on-results
godot --headless --path . -- --join=127.0.0.1 --ftp=150 --autopilot=150 --timescale=3 --exit-on-results
```

`tests/run_all_tests.sh` runs all of the above. Other options are listed at the
top of `scripts/autoload/dev_tools.gd`. For example, `-- --solo` skips the menu
when launching from a terminal.

---

## 6. Known limitations

- Keyboard simulation only; no real trainer input yet (by design for this milestone).
- Internet play is untested. LAN and same-machine play were tested.
- Players can't join a mission already in progress; join in the lobby.
- Placeholder visuals and procedural sounds throughout.
- Zombies along the roadside are scenery. Only the horde can catch you.
